# 对话回答小样本 0.1.0

用途：检查模型对同一已审核主问题的追问与反馈是否随回答变化。这是评测材料，不是正式题库；本项目目前没有可发布的主问题 ID 或评分表。

测试主问题：`请解释 HTTP 请求的幂等性，并说明创建订单的 POST 在重试时如何避免重复创建。`  
技术依据：KB-BE-02；来源 S-HTTP-01、S-HTTP-02。

| 类型 | 模拟回答 | 人工期望观察点 |
| --- | --- | --- |
| 完整 | “幂等看同一请求重复执行对服务端最终状态的预期效果，不要求每次返回相同状态码。GET、PUT、DELETE 按方法语义是幂等的；POST 创建订单默认不是。客户端为同一次下单重试复用幂等键，服务端在数据库中对键加唯一约束并用事务记录结果，重复请求返回已有结果。不同业务操作不能共用同一个键。” | 能指出定义、方法示例、业务约束与重试边界；追问可深入键有效期或并发冲突，不应说答案完全错误。 |
| 含糊 | “幂等就是多请求几次也差不多。订单接口可以加个标识避免重复。” | 追问“差不多”具体是状态还是响应，以及标识存在哪里、并发时如何处理；反馈指出缺少精确定义。 |
| 错误 | “POST 本来就是幂等的。只要前端禁用按钮，服务端就不会收到重复下单请求。” | 明确指出 POST 默认不保证幂等、禁用按钮无法覆盖网络重试或并发；反馈引用相应技术依据，不把错误答案评为正确。 |
| 不会 | “不会。” | 不编造用户已掌握的知识；可给一个低门槛引导问题或结束该题，并在反馈中标记未展示能力。 |

人工审核时检查：追问是否针对该回答的具体缺口；技术判断是否有可用证据；引用是否真的支持判断；示范回答是否把 JD 或个人陈述误当技术依据。实际结果由用户测试后记录。
