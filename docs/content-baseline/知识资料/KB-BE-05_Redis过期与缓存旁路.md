# Redis 过期与缓存旁路

资料 ID：KB-BE-05  
能力：BE-REDIS  
适用范围：Redis 字符串缓存与键过期  
版本：0.1.0  
依据：S-REDIS-01、S-REDIS-02、S-REDIS-03

## TTL 与过期

给 Redis 键设置过期时间后，键会在时限到达后被视为过期。`EXPIRE` 用于给已有键设置过期秒数，`TTL` 可查询剩余秒数；`TTL` 返回 `-1` 表示键存在但无过期时间，`-2` 表示键不存在。缓存设计应明确哪些数据允许短时间陈旧，以及过期时间如何选取，不能只说“加 Redis 就能解决一致性”。

## 缓存旁路

常见的 cache-aside 读取流程是先查缓存；未命中时读取数据库，再把结果写入缓存，并设置适当过期时间。写入数据库后，应按业务需要删除或更新相关缓存，考虑并发读写和失败重试。缓存不是数据库事务的一部分，因此写入成功与缓存变化之间可能出现短暂不一致。

## 缓存失效场景

如果大量请求查询根本不存在的记录，重复落到数据库会形成压力；可以按业务要求短暂缓存空结果，注意数据稍后创建时的失效处理。热点键同一时间过期也可能导致集中回源，可考虑请求合并、互斥重建或过期时间分散。具体机制应结合流量和一致性要求选择，不能把这些策略说成 Redis 命令自身的保证。

## 面试判断边界

TTL 是过期管理，不等于内存淘汰策略。`TTL=-1` 不表示键已失效；给缓存设置过期时间也不保证更新后立刻读取到最新数据库值。
