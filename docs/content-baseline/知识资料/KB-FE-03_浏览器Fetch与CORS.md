# 浏览器 Fetch 与 CORS

资料 ID：KB-FE-03  
能力：FE-BROWSER  
适用范围：浏览器 Fetch API 与跨源请求  
版本：0.1.0  
依据：S-WEB-01、S-WEB-02

## Fetch 的结果处理

`fetch()` 返回 Promise。网络错误等情况会使 Promise 拒绝，但服务器返回 404 或 500 时，通常仍得到一个 `Response`；调用方要检查 `response.ok` 或状态码，再决定是否把它当成业务错误。`response.json()` 解析响应体也可能失败，不能把拿到 `Response` 等同于一定获得可用 JSON。

## CORS 的作用

浏览器在跨源脚本读取响应时应用同源策略，并通过 CORS 响应头决定是否允许访问。某些请求会先发送预检请求。CORS 由服务器提供许可，前端在 `fetch` 中随意添加一个 `Access-Control-Allow-Origin` 请求头不能解决缺少服务器许可的问题。开发代理能改变本地开发时的请求路径，但不等于生产环境跨源策略已配置正确。

## 凭证与错误定位

带 Cookie 的跨源请求还涉及凭证模式及服务端允许的来源和凭证设置。浏览器报 CORS 错误时，应检查请求的来源、方法、预检、服务器响应头和重定向，而不应只把它当成接口“没有启动”。同时，CORS 是浏览器访问控制机制，不代替服务端身份验证或授权。

## 面试判断边界

“`fetch` 遇到 404 会直接进入 `catch`”和“设置 `mode: 'no-cors'` 就能读取跨域 JSON”都不能作为通用做法。应分别判断 HTTP 响应状态和浏览器是否允许读取响应。
