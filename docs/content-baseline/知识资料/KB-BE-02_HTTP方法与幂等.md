# HTTP 方法与幂等

资料 ID：KB-BE-02  
能力：BE-HTTP  
适用范围：HTTP 方法语义  
版本：0.1.0  
依据：S-HTTP-01、S-HTTP-02、S-HTTP-03（工作组草案）

## 方法语义

`GET` 用于获取资源表示，属于安全方法；安全指客户端请求的预期语义不要求改变服务端状态。`PUT` 用于创建或替换目标资源的表示，`DELETE` 请求删除目标资源，`POST` 则把表示交给目标资源按自身语义处理，例如创建一个新订单。设计接口时应让业务操作与方法语义相符，不能仅靠路径名称判断是否安全或幂等。

## 幂等的判断标准

幂等是同一请求执行一次和执行多次，对服务端预期状态产生相同效果。它不要求每次响应体或状态码完全一样。按照 HTTP 方法语义，`GET`、`PUT`、`DELETE` 是幂等的，`POST` 默认不保证。比如重复删除同一资源，第一次可能成功，之后可能返回“资源不存在”，但资源最终都处于已删除状态。

## 业务重复提交

网络重试可能使服务端收到同一业务意图多次。对于创建订单等 `POST` 操作，可以设计幂等键：让客户端为同一次业务操作重复使用相同键，服务端在持久层约束并发请求，返回已有处理结果。仅在内存里检查“是否提交过”不足以覆盖多进程、重启和竞态。幂等键是应用层设计，不能把所有 `POST` 自动视为幂等。

## 面试判断边界

“DELETE 是幂等的，所以每次都返回 200”混淆了状态效果与响应；“GET 不修改数据库中的任何字节”也过度绝对化，日志或计数等附带实现细节不改变其请求的安全语义。
