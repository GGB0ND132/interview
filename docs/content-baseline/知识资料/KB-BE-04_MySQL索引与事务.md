# MySQL 索引与事务

资料 ID：KB-BE-04  
能力：BE-MYSQL  
适用范围：MySQL 8.4、InnoDB  
版本：0.1.0  
依据：S-MY-01、S-MY-02、S-MY-03

## 索引和执行计划

索引帮助优化器更快定位候选行，但也占用空间并增加写入维护成本。对慢查询先确定实际 SQL、筛选条件、排序、表规模和数据分布，再使用 `EXPLAIN` 查看执行计划。执行计划提供优化器的估计和访问方式；“用了索引”并不自动说明查询已足够快，仍应结合真实运行数据分析。

## 多列索引

多列索引按列顺序组织。索引 `(a, b, c)` 可以利用从最左列开始的前缀，例如 `(a)`、`(a, b)`；仅按 `b` 过滤不能简单假定同样按该复合索引直接定位。是否使用、使用多少列以及能否同时服务排序，还受查询表达式和优化器选择影响。建索引应围绕真实查询模式，而不是给每个字段各建一个索引。

## 事务隔离

InnoDB 支持常见的四种事务隔离级别，包括 `READ COMMITTED` 与默认的 `REPEATABLE READ`。隔离级别影响并发事务如何读取数据，但不能把某个级别简单等同于“完全没有并发问题”。普通一致性读和加锁读有不同规则；涉及库存扣减或唯一业务约束时，还要结合锁、唯一约束和事务边界设计。

## 面试判断边界

“建索引一定使所有查询变快”“事务用了可重复读就不可能超卖”都缺少条件。合理回答应给出 SQL、数据和并发场景，再解释如何用执行计划与事务方案验证。
