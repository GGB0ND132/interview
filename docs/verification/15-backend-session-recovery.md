## 已验证行为

- 两种模式分别让独立子进程在模型调用中 `os._exit(19)`，新进程/应用接管原 job，原答案、问题和提交 ID 不变，最终只有一份结果；重复提交仍返回已保存提交。
- 两种模式分别启动真实 uvicorn TCP 服务，在外部评价调用中强制 kill 服务进程，再启动同库服务自动接管。模拟面试继续问完得到 `completed`，单题练习得到已完成反馈。历史总数为 1；再次重启后会话和报告逐项一致。
- 两种模式分别验证超时、非法输出、限流、检索阶段失败和未预料的适配器异常：失败保留答案、没有半成品反馈，错误公开阶段及 `retry` 动作。重启后失败状态相同；两个并发 retry 返回同一 job ID，只有一个提交成功。HTTP 429 在实际 HttpEvaluator 边界另有回归验证。
- 同库两个应用并存时，未到期租约保持原执行；过期后允许重新领取。旧执行返回 1 分的迟到结果，不能覆盖新执行的 75 分，也不能再次改变会话、追问或阶段。
- 从原始五列 jobs 表构造 schema 4 的 queued/running 中断任务，自动升级后均通过 HTTP 获取成功反馈。
- 四个服务同时启动 schema 4 数据库，在写锁内重新核对版本并只升级一次，四者读取同一份会话。该测试在修正前复现重复字段错误，在修正后通过。
- 并发修改返回 409 `STATE_CONFLICT` 与 `refresh_session` 动作。先前 01/07 的提交去重、追问去重、评分隐藏、终止与覆盖率回归继续通过。

## 边界

所有验收库位于 pytest 临时目录；没有修改其他工作区数据库、发布服务或调用收费模型。真实进程与 TCP 中断验收使用明确的受控外部评价适配器，验证持久化和执行语义，不作为模型评分质量验证。本依赖分支未接入工单 13 的在线检索；检索失败在适配器边界注入并验证阶段定位与保留原任务重试，不声称完成真实检索端到端或检索内部断点恢复。

默认运行租约至少 150 秒、随模型超时上调；进程中断可等待剩余租约。无租约续期，过长外部调用可能重新发生，数据库写入由令牌隔离，无法保证外部服务恰好调用一次。未提交草稿恢复属于 16。
