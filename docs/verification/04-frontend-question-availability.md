# 04：前端题库可用性与缺口验收

日期：2026-11-09。实施分支：`GGB0ND132/04`。基线：`f855c1844f5472a55225160fabce054be70007db`，已包含 02/03；从原分支快进同步，没有修改 main。

## 实现范围

- `/question-practice` 提供试题练习与模拟面试模式选择，按题包、难度、主题查询真实可用性。默认选择 MianStack 题包，不用样题数量冒充正式题包数量。
- 主题目录包含可用与零题主题。总数按当前筛选计算，抽题携带同一筛选；无题、查询中或查询失败时禁用开始。
- 刷新按钮、整页刷新和从会话返回入口重新查询。每次筛选使用独立请求身份，迟到响应不能覆盖新选择，切回以前的筛选也必须等新结果。
- 模拟面试列出开场、经历或假设情境、技术、行为与候选人反问。当前仅有技术发布入口，其他环节为缺口；至少 3 个有适合面试题目的技术主题才覆盖技术部分。模拟面试流程仍由 07/08 实现，当前入口明确禁用，不生成主问题。
- 首页和品牌链接进入真实练习入口；旧流程保留为“面试演示”。
- 遵循现有 UI 字体、表单和颜色变量，仅为环节、主题列表增加样式；展开主题目录查看完整缺口，避免把候选取材数当作可评分数量。

## 测试边界与 TDD

沿用阶段规格 Testing Decisions 指定的两个外部边界：维护/可用性 HTTP 接口、浏览器可见练习行为。组件测试用服务端客户端边界替身控制延迟及失败，不模拟内部组件或数据库实现。

逐项 red → green：主题目录测试先因缺少 `topics` 失败；模拟面试可用性先因 422 失败；页面主题筛选先因缺少控件失败；切回旧筛选的回归测试先捕获旧结果启用开始按钮，再用每次查询的独立身份与取消标记修复。

最终自动验证：前端 `npm test` 20 项，后端 `uv run pytest -q` 58 项；`npm run build`（含 TypeScript）、`npm run lint`、`uv run mypy`、`uv run ruff check .` 均通过。

后端有一条现有 Starlette/httpx 弃用提示，不影响测试通过。此工单不调用模型，真实模型评分验收沿用 02 的已存记录，不声称重新验证评分。

## 真实浏览器验收

前端 Vite `http://127.0.0.1:5174`，代理到本工作区 FastAPI `http://127.0.0.1:8000`。独立数据库：`backend/data/04-availability-browser.sqlite3`。浏览器未拦截或伪造任何 API 响应。Tabbit 启动器两次无输出退出 1，改用可用的 Playwright CLI 创建独立浏览器会话 `availability04`。

| 外部状态 | 操作与观察 |
| --- | --- |
| 无题 | 全新 MianStack 题包显示无可评分题、12 个零题主题，随机抽题按钮禁用。 |
| 发布后有题 | 经真实发布接口导入示例 Q-0058/Q-0140，接受 2、拒绝 0、新增 2；发布 ID `8a7cae64-395a-4661-ab8d-099c529264ee`。点击刷新变为 2 道可抽。 |
| 主题筛选与抽题 | 选择 `agent_loop` 后为 1 道可抽，点击后实际显示 `题目 Q-0058 · 版本 1`；返回入口保留筛选并重新查询。 |
| 环节缺失 | 全主题模拟面试显示 2 个技术主题、至少需 3 个；四个非技术环节为 0，技术覆盖不足，流程未接入，开始按钮禁用。 |
| 题目停用 | 经维护接口停用 Q-0058 v1；刷新模拟面试后只剩 1 个主题；切回试题练习总数 1，筛选 `agent_loop` 变为 0 且禁用开始。 |
| 整页刷新 | 停用后 reload 显示总数 1；再次选择 `agent_loop` 仍为 0，不回退旧题目版本。 |

Playwright 断言检查了按钮禁用与实际抽题 ID。已查看完整页面截图及 390px 页面，无水平溢出。截图保存在本地忽略目录：`output/playwright/04-missing-stages.png`、`04-disabled-question.png`、`04-mobile.png`。页面只有原有缺失 favicon 的 404，无应用脚本报错。

复现：使用独立空数据库启动本分支后端与前端，打开 `/question-practice`；按 backend/README 的发布命令导入 `mianstack_example.json`，刷新并切换模式/主题；调用 Q-0058 停用接口后再次刷新。不要对日常题库运行停用验收。
