# 17：进程恢复回归不稳定修正

用户报告：任务成功、回答仅保存一份，但 attempts 为 3，原断言要求 2。

根因是测试给被杀进程和正常接管进程都设置了 0.2 秒租约。被杀进程需要短租约加快接管；正常进程的调度、模型边界和提交可能超过 0.2 秒，提交时租约已失效，后台再次领取导致第三次尝试。生产默认租约已根据完整模型/资料核验预算计算，本次没有修改生产租约、计次或 fencing 规则。

在既有双模式测试中，于 evaluator 边界推进测试时钟 0.3 秒，保留原 0.2 秒租约时稳定复现 `assert 3 == 2`。随后仅让正常接管进程使用默认任务预算，被杀进程仍用 0.2 秒；TCP 场景同样仅为刻意被杀的 worker 保留 0.4 秒租约。模拟耗时和 `attempts == 2` 断言保留，仍检查唯一会话、唯一回答、原题不变、幂等重放及重启后报告全等。
