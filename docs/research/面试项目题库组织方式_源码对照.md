# 面试项目题库组织方式：源码对照

核对日期：2026-11-09。范围为四个公开仓库的固定提交；只做源码静态核对，未运行模型、数据库或网站服务。公开仓库不等于在线产品全部实现。

## 结论

不能把这几个项目都概括成“按岗位和能力标签从结构化题库查题”。DeepInterview 检索岗位面试包后让模型编排；AI-Interview-Agent 使用模板与模型生成；llm-interview-coach 使用 Markdown 主题题库与岗位指导；MianStack 的公开内容最接近一题一记录的可维护题库，但网站岗位映射等关系不在其公开内容仓库中。

这些实现可以参考，却不等于本项目当前“已审核、已发布题库提供正式主问题”的运行约束。方案参见 [题库建设与运行流程](../题库建设与运行流程.md)。

## 1. DeepInterview：一岗位面试包一份 Markdown

固定提交：`bd6d136fffc509265bc2355e95101e0ad7f56eac`。

- 存储在根目录 `skills/*.md`，该快照有 30 个带 frontmatter 的顶层面试包文件。这是包数量，不是独立题目数量。
- 包头字段包含 `id`、`company`、`role`、`level`、`competency`、`version`、`source_runs`、`confidence`、`last_verified`、`status`。
- 正文按 `Round structure`、`Question bank`、`Signals`、`Pitfalls` 分段：分别表示流程、参考题、正向评价信号、常见问题。
- 初级后端包的实际标签是 `role: backend-engineer`、`level: junior`，能力为 `fundamentals`、`debugging`、`code-quality`、`communication`。其 `Question bank` 段是 7 条 Markdown 问句；示例未对每条问句分别设置题号和能力 ID。

来源：[初级后端包第 1 行起](https://github.com/ngoanpv/DeepInterview/blob/bd6d136fffc509265bc2355e95101e0ad7f56eac/skills/generic-backend-engineer-junior.md#L1)、[包字段说明第 5 行起](https://github.com/ngoanpv/DeepInterview/blob/bd6d136fffc509265bc2355e95101e0ad7f56eac/skills/SCHEMA.md#L5)。

实际选择路径：

```text
解析候选人和 JD，分析能力差距
  → find_relevant(company, role, level, limit=2)
  → 选出匹配的面试包
  → 截取包中相关正文，合计上限 1500 字符
  → 交给模型生成 QuestionPlan
```

`find_relevant` 按岗位名称分词及同义形式匹配；公司为指定公司或 generic；级别只影响排序，不作严格排除；再按状态与随时间衰减的置信度排序。**函数没有 competency 参数，也没有逐题按能力标签过滤。** 能力差距进入模型提示词，模型为生成的每道计划题设置 `target_competency`、难度、rubric 和 followups。

来源：[实际检索函数第 235 行起](https://github.com/ngoanpv/DeepInterview/blob/bd6d136fffc509265bc2355e95101e0ad7f56eac/apps/agent/src/deepinterview_agent/skilllib/store.py#L235)、[面试包正文提取与模型调用第 218 行起](https://github.com/ngoanpv/DeepInterview/blob/bd6d136fffc509265bc2355e95101e0ad7f56eac/apps/agent/src/deepinterview_agent/prep/nodes.py#L218)、[计划题字段第 130 行起](https://github.com/ngoanpv/DeepInterview/blob/bd6d136fffc509265bc2355e95101e0ad7f56eac/apps/agent/src/deepinterview_agent/shared_models.py#L130)、[规划提示词第 151 行起](https://github.com/ngoanpv/DeepInterview/blob/bd6d136fffc509265bc2355e95101e0ad7f56eac/apps/agent/src/deepinterview_agent/prep/prompts.py#L151)。

## 2. AI-Interview-Agent 与 llm-interview-coach

两仓库的逐项代码路径、固定提交与来源链接见 [补充核对](面试项目题库源码核对_子项.md)。

- AI-Interview-Agent：静态句式模板与岗位变量，加上 JD/简历驱动的模型生成。必须区分初始题目列表与实际每轮 `next_question_text` 生成路径，不能因为出现 `initial_questions` 就称其为按标签查库。
- llm-interview-coach：主题题目 Markdown + 岗位重点说明，由模型结合文档选择和追问；不是带查询 API 的逐题关系数据库。

## 3. MianStack：一题一文件，JSON 元数据与答案正文分开

固定提交：`b1e033dd72db1d4e23fa0c5b8d0ae28fd330de77`。该快照 `questions/` 下有 8429 个 `Q-*.md` 文件；数量不表示这些题都有完整答案或已经按本项目标准审核。

主要目录：

```text
questions/Q-0193.md       标准题元数据 + 答案正文
categories.json          分类与所属专题词表
schema/content.schema.json  字段、枚举与约束
interviews/              真实面经，含岗位情境元数据
collections/             公开题集条目及出处
scripts/lib/content.mjs  公开内容加载与校验
scripts/build-indexes.mjs  按分类、专题等生成索引
```

`Q-0193.md` 的实际元数据如下（取自来源，只展示关键字段）：

```json
{
  "id": "Q-0193",
  "title": "B 树和 B+ 树有什么区别？",
  "category": "software",
  "topic": "数据库与 SQL",
  "type": "比较选型",
  "level": "进阶",
  "priority": "按岗位选读",
  "answerStatus": "ready"
}
```

题目还支持 `focus`、`note`、`aliases`、`formatTags`、`contextTags`、`updatedAt`。答案是 frontmatter 后的 Markdown，示例包含核心回答、原理说明、常见追问和参考资料。`answerStatus` 用于区分答案状态，不能把全部题目文件都视为已有完整答案。

来源：[真实题目第 1 行起](https://github.com/didilili/mianstack/blob/b1e033dd72db1d4e23fa0c5b8d0ae28fd330de77/questions/Q-0193.md#L1)、[字段语义第 28 行起](https://github.com/didilili/mianstack/blob/b1e033dd72db1d4e23fa0c5b8d0ae28fd330de77/schema/README.md#L28)、[分类与专题索引生成第 213 行起](https://github.com/didilili/mianstack/blob/b1e033dd72db1d4e23fa0c5b8d0ae28fd330de77/scripts/build-indexes.mjs#L213)。

**公开边界：题目 frontmatter 不含 `roleFamilies`；题目与来源映射、追问顺序、题族和题间关系由网站另行维护，不属于这个公开仓库的加载结果。** 因此可以确认其分类与题目组织，不能从公开仓库推断已完整获得在线网站“岗位 → 题目”的关系及排序算法。面经中的岗位元数据也不能直接当成每道标准题自带岗位标签。

来源：[公开内容边界第 9 行](https://github.com/didilili/mianstack/blob/b1e033dd72db1d4e23fa0c5b8d0ae28fd330de77/schema/README.md#L9)、[题目不包含岗位字段第 49 行](https://github.com/didilili/mianstack/blob/b1e033dd72db1d4e23fa0c5b8d0ae28fd330de77/schema/README.md#L49)。

## 对本项目的含义

本项目可以参考 MianStack 的稳定题号、受约束的分类、答案状态和正文组织；参考 DeepInterview 的面试包结构、能力对齐及评分信号。但“正式主问题按岗位与能力标签筛选”是本项目自己的明确要求，并非这四个仓库共有的现成功能。

按已有项目方案，结构化题目应维护 `role_tracks`、`competency_ids`、`difficulty`、`stage`、审核状态、答案、评分点及来源版本。程序筛选已发布题目，模型负责回答驱动的追问与评价。通常用业务数据库字段查询即可，不必先把题目向量化才实现这些条件。

这份笔记不改变现有架构，也没有把第三方题库批量导入为正式发布题目。
