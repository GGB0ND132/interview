版本：V2.1 · 简洁现代方向

## 1. 最终方向

**以 Notion 的白色工作台为主参考：窄导航、清晰文字、轻量列表、充足留白。面试区只保留一个阅读中心，资料引用在需要时展开。**

整体感觉：像打开一个整理好的工作文档。用户第一眼看到正在做的事情，第二眼看到下一步操作，最后才是辅助信息。

本版统一采用白底、黑灰文字、黑色主按钮和少量蓝色链接。全站保持同一套字体、图标和组件尺度。

## 2. 信息架构

一级导航固定为三个页面，顺序为：**面试练习、资料管理、历史记录**。

| 页面 | 默认看到什么 | 深一层看到什么 |
| --- | --- | --- |
| 面试练习 `/practice` | 无进行中练习时显示简洁配置；有练习时直接恢复问答 | 题组反馈、引用抽屉、结束后的报告入口 |
| 资料管理 `/materials` | 岗位与知识库选择、文档列表 | 岗位 JD 与能力编辑、文件详情、检索测试 |
| 历史记录 `/history` | 可筛选的会话列表 | 单场报告、问答时间线、引用快照、同岗位薄弱点 |

不额外增加首页、数据大屏或学习仪表盘。配置、报告和文件详情是对应主页面内的视图，不占一级导航。

## 3. 统一页面骨架

### 3.1 桌面布局

按 1440 × 900 的桌面画布设计，同时兼顾 1280 × 720 的常见窗口。

| 区域 | 规范 |
| --- | --- |
| 左导航 | 宽 208px，全高；背景 `#F8F9FA`，右边界 1px |
| 顶部栏 | 高 56px；白底，只放当前页面名和必要的页面操作 |
| 内容区 | 上下留白 40px，左右至少 40px；资料和历史最大宽度 1080px |
| 面试正文 | 最大宽度 760px，居中；打开引用时形成正文与抽屉的关系 |
| 引用抽屉 | 宽 360px，上限为窗口宽度；打开后保持正文阅读位置 |
| 弹窗 | 常规宽 480px；需要编辑长内容时宽 640px |

主区有且只有一个页面标题。顶部栏只承担导航菜单、返回、状态或上下文操作，不重复正文标题；默认列表页的标题在正文中，答题页顶部栏显示岗位上下文。

### 3.2 导航内容

顶部只放产品文字名称“面试练习”，字号 16px、字重 600。品牌名未确定前，不新增口号、英文副标和装饰图形。

导航项高 36px，图标与文字间距 8px，左右内边距 12px。选中项为浅灰底与深色文字，其他项为中灰文字。

底部仅保留“使用说明”文字入口。单用户 V1 不展示头像、组织切换、账户菜单、会员升级或通知中心。

## 4. 色彩、字体、图标与形状

### 4.1 色彩

| Token | 色值 | 用途 |
| --- | --- | --- |
| Canvas | `#FFFFFF` | 主页面与正文背景 |
| Sidebar | `#F8F9FA` | 左侧导航背景 |
| Subtle | `#F3F4F6` | 选中导航、轻量悬停、代码背景 |
| Text / primary | `#18181B` | 标题、正文、主要标签 |
| Text / secondary | `#52525B` | 文件信息、解释文字、次级操作 |
| Text / muted | `#71717A` | 时间、占位提示、辅助说明 |
| Border | `#E4E4E7` | 输入框、列表分隔线、抽屉边界 |
| Primary | `#18181B` | 当前屏唯一的主要按钮 |
| Primary / hover | `#27272A` | 主按钮悬停 |
| Link | `#2563EB` | 可点击来源、文本链接、焦点环 |
| Link / subtle | `#EFF6FF` | 少量链接选中背景 |
| Success | `#166534` / `#F0FDF4` | 已就绪、已完成的小状态 |
| Warning | `#92400E` / `#FFFBEB` | 暂停、等待处理的小状态 |
| Danger | `#B91C1C` / `#FEF2F2` | 错误原因、危险确认 |

前景与背景按表中对应关系使用。整体观感以白、黑、灰为主；蓝色用于链接，不铺成整块主题背景。绿色只出现于小型成功状态。辅助文字在正常字号下也应清楚可读。

禁用状态同时使用“不可操作的按钮样式”和原因说明。状态标记同时包含图标或文字，不能只凭颜色辨认。

### 4.2 Type

字体统一为 **Geist + Noto Sans SC**；本地回退为 PingFang SC、Microsoft YaHei、sans-serif。代码片段使用 JetBrains Mono。

| 层级 | 字号 / 字重 / 行高 | 使用位置 |
| --- | --- | --- |
| 页面标题 | 24px / 600 / 34px | 三个主页面名称、报告标题 |
| 当前问题 | 22px / 600 / 34px | 一道题的核心问题 |
| 区块标题 | 16px / 600 / 24px | 岗位要求、反馈分组、文件详情 |
| 正文 | 16px / 400 / 28px | 问题说明、回答、反馈、来源片段 |
| 表单与列表 | 14px / 400–500 / 22px | 标签、文件名、导航、按钮 |
| 元信息 | 13px / 400 / 20px | 时间、题组进度、状态、文件大小 |
| 代码 | 13px / 400 / 22px | 资料中的 SQL、代码和字段名 |

正文按中文长文阅读设计，不把大段说明缩成 10–12px。正文最大宽度控制在约 40–46 个汉字。标题靠字号与字重区分，减少不同字体和英文标签。

### 4.3 Icon

全站统一使用 [Lucide](https://designeer.xyz/resources/lucide)，常规 18px、描边 1.75px；行内辅助图标 16px。图标保持中性灰，跟随选中项变深。

| 功能 | 图标 |
| --- | --- |
| 面试练习 / 资料管理 / 历史记录 | MessagesSquare / FolderOpen / History |
| 开始 / 下一题 / 提交 | Play / ArrowRight / ArrowUp |
| 来源 / 文档 / 搜索 | BookOpenText / FileText / Search |
| 暂停 / 继续 / 跳过 | Pause / Play / SkipForward |
| 上传 / 重试 / 更多 | Upload / RotateCw / MoreHorizontal |
| 关闭 / 返回 | X / ArrowLeft |
| 成功 / 提醒 / 错误 | CheckCircle2 / Info / CircleAlert |

一级导航与关键按钮保留文字。图标不铺彩色底块。纯图标操作有悬停提示、键盘焦点和可访问名称。

### 4.4 间距与组件

采用 4、8、12、16、24、32、40、48px 间距。图标与文字间距 8px，表单项间距 20px，主要内容段之间 24–32px。

按钮与普通输入框高 36–40px，圆角 6px。多行回答框圆角 10px，弹窗圆角 12px。普通内容不带阴影；抽屉和弹窗允许一层轻阴影。

每屏一个主要动作，黑底白字。其他操作使用边框按钮或文字按钮。删除确认才使用红色实心按钮。

## 5. 面试练习页

### 5.1 进入页面：配置或恢复

无进行中练习时，页面显示标题“面试练习”，下方一个居中的配置表单，宽 560px。说明只用一句：“选择岗位和资料，开始一次有依据的练习。”

| 表单顺序 | 内容 | 展示方式 |
| --- | --- | --- |
| 1 | 目标岗位 | 单选；旁边次级入口“查看岗位要求” |
| 2 | 使用的知识库 | 单选；下方显示可用文件数量 |
| 3 | 面试类型 | 技术、项目、行为；可组合选择 |
| 4 | 难度 | 基础、进阶、挑战；单选 |
| 5 | 主问题数 | 默认 5，道数范围 3–10 |
| 6 | 每题追问上限 | 默认 2，范围 0–2 |
| 7 | 练习重点 | 综合练习，或已有能力项 |

前四项默认可见；主问题数、追问上限、练习重点收进“更多设置”，入口旁显示“5 道主问题 · 最多 2 次追问”。展开后就地编辑，收起时保留已选值。全部选项仍按表中顺序阅读，不把七项配置同时铺满首屏。

主按钮为“开始练习”。岗位或知识库未准备好时，按钮禁用，并在对应字段附近放“先添加岗位”或“去上传资料”。

有未结束练习时优先恢复当前会话。暂停的会话顶部显示“练习已暂停”和“继续练习”；用户主动选择“新建练习”时再进入配置。

### 5.2 练习中：一个问题，一个回答区

顶部上下文栏显示“后端开发工程师”，右侧文字按钮“查看配置”。正文题目上方一行元信息：“主问题 2 / 5 · 进阶”；出现追问时，追问自身另标“追问 1 / 2”，不在多个位置重复进度。

正文从上到下只有三层：

1. **面试官问题**：22px 题目；16px 场景说明；一条“资料来源 · 1”入口。
2. **问答记录**：已提交回答和后续追问按顺序排列；角色名称用 13px 灰字。
3. **当前回答框**：正文列底部固定；上方问答区域自然滚动。

面试官内容直接放在白色页面上。用户回答可用 `#F3F4F6` 的轻底色块，内边距 16px。题目、提示、来源各自不再套卡片。

回答框初始可输入约 4 行，最大约 10 行；长内容在框内滚动。底部左侧放“Ctrl + Enter 提交”，右侧放字数与黑色“提交回答”按钮。未输入时提交按钮禁用。

输入区下面一行次级操作：“暂停”与“不会，跳过”；“结束练习”放到更多菜单，降低误触。操作文字字号至少 13px。

页面不展示完整题目目录、答题技巧常驻栏、装饰性时间线和大面积状态标签。进度使用实际完成题组数；追问不增加主问题数量。

### 5.3 准备与处理

开始后在同一内容位置显示简短阶段：“正在准备面试计划”“正在检索资料”“正在准备第 1 题”。保留岗位和配置摘要。

答案提交后先显示“回答已保存”，再显示“正在整理追问”或“正在生成本组反馈”。答案继续可见；提交与推进操作暂时禁用。

不展示推算百分比，不以逐字动画人为拖慢已经完成的内容。

模型处理期间暂不可暂停、结束或跳转下一题，相关入口禁用并说明“处理完成后可操作”。暂停与结束遵循当前可用操作，不表现为可以立即取消远端生成。

### 5.4 追问

追问接在用户上一条回答之后，标签为“追问 1 / 2”。当前输入框清空，焦点回到回答区。

用户回看之前回答时保持当前位置；底部可出现“查看新追问”的小型文字提示，由用户决定跳转。

### 5.5 题组结束：就地反馈

题组结束后，在问答末尾显示“本组反馈”，输入框切换为底部“下一题”操作区。当前主问题、回答与追问仍能回看。

反馈按以下固定顺序展示，不做左右多卡片拼接：

| 顺序 | 内容 | 表现形式 |
| --- | --- | --- |
| 1 | 一句话结论 | 16px，说明本题最值得改进的地方 |
| 2 | 维度评价 | 准确性、覆盖、相关性、结构、具体性；文字与分数对齐成行 |
| 3 | 回答中的具体问题 | 引用用户原句，再给出可执行改法 |
| 4 | 示范回答 | 默认折叠，点击后展开正文 |
| 5 | 资料依据 | 文件名与引用编号，点击打开抽屉 |

综合分数作为辅助信息使用 24px 数字，避免占据页面视觉中心。不使用雷达图和多色评分卡。

跳过的题组显示“已跳过，本题不计分”，提供查看学习依据与进入下一题的入口。无可评价内容时使用“未评价”，不显示 0 分。

最后一组的主按钮改为“查看整场报告”。

### 5.6 资料引用抽屉

默认关闭。点击来源入口后从右侧展开，标题“资料依据”。从上到下依次为：文件名、版本、章节或可靠页码、引用片段、关闭操作。

题组进行中可以查看文件和来源元信息，原文默认折叠，并标注“题组结束后可查看原文”。题组结束后直接阅读原文片段。历史中的引用展示当时保存的快照。

抽屉是页面内同级阅读区域；桌面窗口足够宽时压缩外围留白，正文宽度尽量不低于 600px。窗口较窄时抽屉覆盖主区，避免把正文挤成细长列。

## 6. 资料管理页

### 6.1 默认视图

顶部标题“资料管理”，右侧唯一主按钮“上传资料”。下方工具行显示“岗位：后端开发工程师”和“知识库：后端学习资料”的下拉选择。

岗位下拉提供创建岗位、编辑岗位和查看已归档岗位；知识库下拉提供创建、重命名与删除入口。较少使用的操作放入菜单，避免每种操作都常驻一个按钮。

工具行下面放搜索框、状态筛选和次级按钮“检索测试”。正文直接进入文档列表。

| 列 | 内容 |
| --- | --- |
| 文件名 | 文件图标 + 名称；必要时第二行显示大小和版本 |
| 状态 | 排队中、处理中、已就绪、失败；文字配小图标 |
| 片段数 | 已知时显示真实数量；未就绪使用破折号 |
| 参与练习 | 启用开关；不可修改时解释原因 |
| 操作 | 行末更多菜单 |

表头高 40px，常规行高 60px，底部 1px 分隔线。悬停整行使用非常浅的灰底。文件名左对齐，数字按列对齐。

已有文件时，上传操作收进主按钮，不再常驻大型拖拽区域。知识库为空时，才在列表位置显示上传空态：“添加第一份学习资料”，下方说明支持 PDF、DOC、DOCX、MD。

### 6.2 文件与版本

点击文件名打开详情抽屉：状态、失败原因、版本、片段数量和预览。更多菜单包含“停用 / 启用”“替换版本”“删除”。

上传时显示实际解析阶段；失败原因紧跟该文件显示，例如“DOC 转换失败”，旁边放“重试”。长解释在详情中展开。

活动会话锁定资料范围时，上传、停用、版本替换和删除等修改操作禁用，并给出“此知识库正用于进行中的练习，结束后可修改”的原因。提示中附占用练习的岗位、创建时间与“查看练习”入口；查看文件和检索测试仍可用。资料不会在用户答题期间悄悄变化。

有尚未完成的资料处理任务时，也不可直接开始锁定资料的练习；配置页显示实际处理状态与“查看资料”入口。

删除使用小型确认弹窗，清楚说明对新练习的影响及历史引用的保留规则。

### 6.3 岗位与能力编辑

点击“编辑岗位”进入宽 640px 的编辑面板，依次排列岗位名称、JD 原文、可选项目背景、能力列表。

粘贴 JD 后主按钮为“分析岗位要求”。返回能力草稿后允许逐项改名、调整优先级、添加和删除；用户确认后保存岗位。

JD 是输入区，能力列表是输出与编辑区，以标题和留白分开。能力项使用普通列表，不做彩色标签云。

归档岗位保留既有历史记录；新练习选择中默认隐藏已归档岗位。

### 6.4 检索测试

点击“检索测试”进入页面内测试视图，顶部有“返回资料”。主体为一行问题输入框与“测试检索”按钮，下方显示片段列表。

每条结果包含文件名、章节或可靠页码、实际片段正文与引用编号。相关性数值只在接口实际提供且定义明确时显示。

无结果时只说明“没有找到相关资料”，给出“换个问题”与“补充资料”入口。结果列表不混入资料上传配置或练习建议。

## 7. 历史记录页

### 7.1 默认列表

标题“历史记录”，右侧“新建练习”按钮。标题下面只放岗位、状态与时间筛选，以及主题搜索。

首屏直接展示记录列表。每行包含：岗位 / 练习主题、时间、主问题组数、状态、可用的综合表现；点击整行进入详情。

不在列表上方增加累计练习、平均分、今日目标等统计卡。聚合内容仅出现在明确选择同一岗位后的“薄弱点”视图，不混合不同岗位评分。

### 7.2 单场详情

顶部“返回历史记录”，标题使用“后端开发工程师 · 练习报告”。下面一行显示日期、题组数量、面试类型与状态。

详情只有两个标签：“报告”“问答记录”。选中态用深色文字与底部细线，其他标签为灰字。

报告为最大宽度 800px 的单列长文：

1. 总体结论与综合表现，说明有效评价样本数量。
2. 需要继续练习的能力，按优先级最多展示 3 项。
3. 各题组摘要，点击定位对应问答。
4. 下一步练习清单，主按钮“按这些薄弱点再练”。

问答记录按时间顺序列出主问题、回答、追问和题组反馈。通过题组锚点定位，不复制一套复杂树形导航。

来源引用沿用同一个抽屉。文档已替换或删除时，仍明确显示该记录所用版本及快照。

已结束会话的“更多”菜单提供“删除记录”。确认弹窗说明会同时删除该场问答、评分、报告与引用快照，并从后续薄弱点统计中移除；删除后回到列表并以短提示确认结果。

### 7.3 同岗位薄弱点

选择岗位后提供“查看薄弱点”入口。进入后按能力列出表现、有效题组数量和来源会话。

样本不足时显示“记录较少，暂不判断为稳定薄弱项”；仍可让用户主动选择该能力练习。跳过、未评价与空分数不按低分计入。

## 8. 关键状态与文案

| 场景 | 页面呈现 | 下一步 |
| --- | --- | --- |
| 首次使用 | “先添加岗位和学习资料” | 去资料管理 |
| 无就绪资料 | 知识库字段下方提示“资料仍在处理中” | 查看处理状态 |
| 依据不足 | 问题位置显示“资料不足，暂时无法生成这道题” | 补充资料或更换主题 |
| 已保存，评价失败 | 保留答案，标注“回答已保存，评价未完成” | 重试评价 |
| 服务暂不可用 | 在当前任务附近显示简短原因 | 重试；不要求重新作答 |
| 练习暂停 | 顶部灰色状态，输入暂时禁用，保留草稿 | 继续练习 |
| 提前结束 | 确认弹窗说明已提交记录保留、未提交草稿不计入 | 继续答题 / 结束并查看报告 |
| 报告生成失败 | 展示已完成的问答，报告位置显示失败 | 单独重试生成报告 |
| 没有历史 | “还没有练习记录” | 开始第一次练习 |
| 搜索为空 | “没有找到匹配的记录” | 清空条件 |

文案直接描述当前状态。避免“稳稳地向前一步”“让每次表达更接近理想”等装饰性语言。错误用“发生了什么 + 可以怎么做”，不把 request_id、worker、模型策略等实现细节塞进主界面。

涉及资料发送给外部服务的实际数据流，在首次上传的简短说明和使用说明中如实呈现。密钥与服务商配置不放进答题流程。

## 9. Motion

动效采用 [Motion](https://designeer.xyz/resources/motion) 或等效原生过渡。重点是解释状态变化，保持文字阅读稳定。

| 交互 | 规范 |
| --- | --- |
| 按钮、行悬停、导航选中 | 120ms，背景与文字颜色过渡 |
| 新问题与反馈出现 | 160ms 淡入，最多上移 4px |
| 折叠示范回答 | 180ms 高度过渡，保持当前阅读位置 |
| 引用抽屉 | 200ms 滑入；背景仅必要时轻遮罩 |
| 普通弹窗 | 160ms 淡入；最多 4px 位移 |
| 提交处理 | 小型状态图标 + 阶段文字；保留用户答案 |

不使用弹跳数字、逐字打字、持续呼吸光效、背景动画、卡片错峰入场和大范围视差。尊重系统“减少动态效果”设置。

## 10. 窄屏规则

| 窗口 | 调整 |
| --- | --- |
| ≥ 1200px | 208px 左导航；单列居中正文；来源可并排展开 |
| 768–1199px | 左导航缩为 184px；来源覆盖展开；主区左右留白 24px |
| < 768px | 导航收进顶部菜单；正文左右留白 16–20px；所有长文单列 |

窄屏配置表单按单列排列；文件列表保留名称、状态和更多操作，文件大小、片段数与参与练习开关移入详情。

移动端引用为全屏阅读面板，顶部固定标题与关闭。输入框跟随可见视口，不被软键盘遮挡；提交按钮保持明确可见，纯图标操作的点击区域至少 44px。

所有输入有常驻标签；键盘焦点采用 2px 蓝色外环与 2px 间隔，不只改变边框颜色。覆盖式抽屉和弹窗限制焦点在当前面板，关闭后返回触发入口；并排的来源阅读区不使用模态遮罩。Esc 关闭非破坏性的面板；有未保存编辑时先确认是否放弃。

Enter 在回答框中换行，Ctrl / Command + Enter 提交；中文输入法组合输入期间不触发快捷提交。题目、反馈与处理状态可由辅助技术获知，整段对话不反复播报。

## 11. 各页面的设计交付清单

以下状态共用上述规范，后续绘制时不另创一套样式。

| 页面 | 需要绘制的状态 |
| --- | --- |
| 面试练习 | 初始配置、正在准备、主问题答题、追问答题、提交处理、暂停、题组反馈、跳过、依据不足、评价失败、结束确认 |
| 资料引用 | 来源元信息、题组结束后的原文、历史快照、来源不可用 |
| 资料管理 | 空库、文档列表、上传处理、解析失败、文档详情、替换版本、删除确认、会话锁定 |
| 岗位编辑 | 原始 JD、分析中、可编辑能力草稿、保存、归档 |
| 检索测试 | 初始输入、有结果、无结果、服务失败 |
| 历史记录 | 列表、筛选为空、单场报告、问答记录、报告失败、同岗位薄弱点 |

## 12. 设计验收标准

- 首屏只有一个最强视觉中心：配置表单、当前问题、文档列表或历史列表。
- 三个主页面使用白色背景与统一黑灰文字，主按钮为黑色。
- 内容不依赖英文眉题、激励文案、装饰卡片来填满空间。
- 面试区默认没有常驻右栏；资料依据通过文字入口按需展开。
- 1280 × 720 窗口下，当前问题和提交区域可用，问答区域独立滚动。
- 问题与回答的字号达到正文规范，辅助信息不抢占主内容层级。
- 每屏只有一个主要动作；其他操作为次级按钮、文字或更多菜单。
- 引用可追溯到真实资料与版本；页码缺失时不补造。
- 题组结束前不展示完整反馈与示范回答；跳过与未评价不按 0 分处理。
- 默认题数 5、追问上限 2；配置保持 V1 支持的范围与面试类型。
- 所有状态均保持同一套组件语言；错误发生后仍能看见并找回已提交答案。
