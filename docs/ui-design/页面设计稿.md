版本：V2.1 · 2026-10-28

本文为 Markdown 页面设计稿，包含布局、示例内容、组件状态与交互。框线表示空间关系，不表示每个内容都需要边框；图中的方括号表示控件。示例岗位、文件、回答、分数与日期均为排版占位，不是实际练习结果。

## 1. 一眼看到的整体效果

主参考为 Notion 工作区。白色正文，浅灰侧栏，黑色主要按钮，蓝色文本链接；用文字层级、行距和分隔线组织内容。

| 维度 | 页面表现 |
| --- | --- |
| 整体 | 安静的文字工作台，以阅读和输入为主 |
| 重心 | 配置页看表单，练习页看问题，管理页看列表，报告页看结论 |
| 留白 | 桌面正文上方 40px；问题与回答之间 24px；反馈区块之间 32px |
| 容器 | 普通正文直接排在白底上；回答框、用户已提交回答、弹窗使用必要容器 |
| 颜色 | 黑灰为常态；链接用蓝色；状态色只出现在状态文字及小标记 |
| 装饰 | 无封面图、渐变、彩色图标底块、积分卡、欢迎横幅 |

桌面基准 1440 × 900。侧栏占 208px，主区占余下宽度。主区内，答题正文最大 760px，列表最大 1080px。下文线框只示意内容顺序；实际绘制按上述尺寸对齐。

[FolderOpen]     资料管理

侧栏左右内边距 12px，导航项高 36px，项间距 4px；产品名与导航组之间留 32px。图标 18px，文字 14px。左边不增加彩色选中竖条。

普通列表页顶部栏保留必要上下文操作，页面大标题在内容区出现一次。答题页顶部栏承载岗位与配置入口，正文从题组进度开始。

## 3. 页面 A：开始练习

无活动会话时进入此屏。表单宽 560px，位于白色主区中间；以左对齐文本组织，不包大卡片。

```text
面试练习
选择岗位和资料，开始一次有依据的练习。

目标岗位
[ 后端开发工程师                           ▾ ]
查看岗位要求

知识库
[ 后端学习资料                             ▾ ]
6 份资料可用于本次练习

面试类型
[✓ 技术]  [✓ 项目]  [ 行为]

难度
[ 基础 ]  [● 进阶 ]  [ 挑战 ]

▸ 更多设置              5 道主问题 · 最多 2 次追问

[ 开始练习 ]
```

页面标题 24px，说明 14px 次级色，两者间距 8px。表单从标题组下方 32px 开始；字段标签与控件间距 8px，字段组间距 20px。主要按钮高 40px、最小宽 112px，距设置入口 24px。

“面试类型”为可多选的普通勾选控件，选中状态有勾号；难度为一组单选控件。默认使用技术、进阶；不预选未经用户确认的项目背景。更多设置展开后显示题数、追问上限与练习重点，正文自然向下延伸。

未创建岗位时，岗位控件下显示“还没有岗位”，相邻入口“添加岗位”。无可用资料时，在知识库字段下说明原因；主按钮禁用。首次使用只保留这一条准备路径，不额外弹出多步引导。

当前主问题 22px / 600 / 34px，说明与对话正文 16px / 28px。问题区默认展开，追问接在回答之后；上一条用户回答使用浅灰底，面试官正文不套气泡。来源是 13px 蓝色文本入口，不额外铺标签墙。

问答区独立滚动，输入区位于该正文列的底部，白色背景，顶部渐变阴影不使用。输入框初始约 140px 高，超过约 10 行后内部滚动。缩短窗口时先减少空白，保留当前问题与可见提交区。

“查看配置”打开只读摘要，练习中不可修改岗位、资料、题数与追问规则。“结束练习”放在右上更多菜单。

### 4.1 输入与提交状态

| 状态 | 输入框 | 操作与信息 |
| --- | --- | --- |
| 空白 | 占位说明“输入你的回答……” | 提交禁用，跳过可用 |
| 已输入 | 常规深色正文 | 提交可用；换行不提交 |
| 提交中 | 保留当前内容，临时只读 | 按钮显示“正在保存”，防止重复提交 |
| 已保存、生成中 | 已提交回答进入问答区 | 显示“回答已保存，正在整理追问”；暂停与结束暂不可用 |
| 生成失败 | 已提交回答原位保留 | 错误旁提供“重试”；不要求重填答案 |
| 暂停 | 草稿保留，输入只读 | 主要动作改为“继续练习” |

“不会，跳过”对当前主问题组结束作答并标为跳过，不跳到未保存的新题；有未提交文字时先确认“跳过将不提交当前草稿”。切换至资料或历史页时保留练习位置与草稿，返回后恢复；关闭页面后的未提交草稿持久化属于后续实现需明确验证的行为，本稿不宣称已经具备。

## 5. 页面 C：本组反馈与资料依据

题组结束后在原问答末尾追加反馈，视图定位到反馈标题；用户正在回看前文时只显示“查看本组反馈”入口。输入区切换为下一题操作栏。

```text

整体思路清楚，需要补充并发情况下的原子性保障。

维度评价
准确性        80          覆盖程度      65
相关性        90          表达结构      70
具体性        60

值得保留
你区分了请求重试与业务重复提交两种情况。

需要补充
“先查询是否存在，再决定写入。”
两次独立操作仍可能发生竞争，可以补充唯一约束
或原子写入方案，并解释失败后的返回规则。

▸ 示范回答

[1] 分布式系统学习笔记.md · 幂等性

─────────────────────────────────────────────────────

```

反馈中的评价行按阅读顺序排列，桌面允许短字段两列对齐，窄屏收成单列；整份反馈始终是一个长文区，不拆成五张评分卡。分数为示例，真实页面只展示服务返回的已计算分数；维度不可评价时显示“未评价”与原因。整组评价不完整时，结论下明确写“部分维度未评估”。

### 5.1 引用展开

```text
资料依据                                      [关闭]
─────────────────────────────────────────────────────
分布式系统学习笔记.md
版本 2 · 幂等性

[1]
“唯一约束可用于阻止同一业务标识的重复写入……”

此处为本次练习保存的资料片段。
```

引用抽屉宽 360px，内边距 24px。文件名 16px / 600，版本与章节 13px 次级色，原文 16px / 28px。优先显示章节；来源没有可靠页码时省略页码。

题组进行中同一个面板只展示文件、版本、章节，并提示“题组结束后可查看原文”；题组结束与历史回看才展示片段。来源快照存在时直接读取快照，原文档被删除不把整个引用变为空态。

宽屏作为并排阅读区；不足以容纳正文时改为覆盖式抽屉，关闭后回到来源入口，保留正文滚动位置。

MD · 128 KB · 版本 2
─────────────────────────────────────────────────────
数据库复习.docx           ◌ 处理中      —      [关]  ⋯

─────────────────────────────────────────────────────

列表顶端距工具行 24px；文件名为深色 14px / 500，附加信息 13px 次级色。只使用横向分隔线，表头浅灰文字，数字右对齐，行末更多操作固定位置。失败行允许增高，不把原因压成不可读的单行。

状态为文字配小图标；已就绪仅状态本身使用深绿。处理中不用虚构进度条。开关旁有可访问的文件名标签，未就绪时不可启用。

### 6.1 上传弹窗

宽 480px，标题“上传学习资料”。中央一个轻边框文件选择区，支持选择文件及拖入文件；下方按顺序列出待上传文件，允许在提交前移除。

格式说明：“支持文字版 PDF、DOC、DOCX、MD。当前每文件上限 10 MiB，PDF 最多 100 页。”容量与数量限制应从当前配置显示；V1 设计起点为每库最多 20 个启用文档，不把这些数字当作已测容量。

首次上传说明资料会发送至所配置的知识检索服务处理，名称按实际配置显示。底部左侧“取消”，右侧主按钮“上传资料”。多个普通文件依次处理，关闭弹窗后可在列表查看状态。

### 6.2 有活动会话时

工具行与列表之间显示一行说明：“此知识库正用于 10 月 28 日的后端岗位练习，结束后可修改。”右侧“查看练习”。上传、替换、启停、删除不可用，检索与预览可用。提示使用浅灰背景，不用整页警告黄。

### 6.3 文件详情

点击文件名打开右侧详情，宽 480px。依次排列文件名、版本与格式、处理状态、片段数量和内容预览。文件操作收在面板右上菜单；失败时原因与重试在标题下方出现。内容预览不声称还原 Word 或 PDF 原始版式。

### 9.1 单场报告

正文宽 800px。标题下是本场真实配置摘要，报告与问答记录通过细下划线标签切换。

综合表现 24px，与正文结论同一内容段；不做巨大分数环。完成数量、计分题组数和评价覆盖率分别表述，避免将答题进度混成评分置信度。示例分数只是排版示意，不承诺模型评价精度。

“问答记录”页签保留题组折叠列表，展开后按主问题、回答、追问、反馈顺序阅读；从报告点击“查看问答”后自动选中该页签并展开对应组。来源沿用相同引用抽屉。

“按这些薄弱点再练”回到配置页并预填岗位与能力重点，仍由用户确认后开始，不直接创建新的练习。

### 9.2 同岗位薄弱点

顶部显示岗位、统计条件与纳入会话数量。正文为能力列表，每项包含“能力名称、表现、有效题组数、来源记录、针对性练习”。默认按优先复习顺序排列。

只聚合同岗位、同能力与相同评分版本的有效结果；不同难度分组展示，不混成单一排名。样本不足显示“记录较少，暂不判断为稳定薄弱项”。没有有效评分时不给出虚构趋势或低分结论，保留主动选择该能力练习的入口。

## 11. 组件与动效交付细节

| 组件 | 默认 | 聚焦 / 选中 | 错误 / 禁用 |
| --- | --- | --- | --- |
| 主按钮 | 黑底白字，40px 高，6px 圆角 | 深灰悬停；蓝色外焦点环 | 禁用灰底，保留原因说明 |
| 次级按钮 | 白底、1px 灰边，36px 高 | 浅灰悬停 | 不用单纯降透明度隐藏内容 |
| 输入框 | 1px 灰边，正文深色 | 蓝色 2px 外环 | 红色边框 + 字段下错误文字 |
| 列表行 | 白底，底部 1px 分隔 | 悬停浅灰；键盘可见焦点 | 失败信息位于本行 |
| 页签 | 灰字，无独立容器 | 深字 + 2px 下划线 | 无内容时仍有说明 |
| 菜单项 | 图标 + 文字，最小高 36px | 浅灰底 | 删除使用深红文字 |
| 提示消息 | 简短文字 + 状态图标 | 成功提示 3 秒后消失 | 需处理的错误留在对应内容区 |

按钮与列表悬停 120ms；新问题淡入 160ms；抽屉 200ms；曲线统一为 `cubic-bezier(0.2, 0, 0, 1)`。只在首次出现时过渡，不在每次状态刷新时重复播放。减少动态效果模式关闭位移和高度动画，使用即时状态切换。
