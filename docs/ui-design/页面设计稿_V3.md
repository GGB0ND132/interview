# 页面设计稿 V3.3

日期：2026-11-09  
视觉与交互基线：[UI.md](../../UI.md)  
旧稿：[页面设计稿 V2.1](页面设计稿.md)

本文只记录页面层面的内容顺序与布局。颜色、字阶、控件状态、断点和可访问性以 `UI.md` 为准。所有示例问题、分数和资料均为演示内容。

## 共用外壳

- 桌面侧栏 220px；产品名、模拟面试、试题练习、资料管理、历史记录四个主导航项、底部使用说明和三态主题控制。侧栏其余空间留白。
- 768px 以下及平板区间侧栏收起，顶部菜单可唤出。顶部栏只显示当前上下文；页面标题只在内容区出现一次。
- 内容区为冷灰纸面，不把整段页面放入卡片。标题使用思源宋体，正文使用无衬线；链接和当前选中用靛青。

内容最大宽 560px，表单字段间距 20px。模拟面试按环节与本场优先能力推进，不显示固定主问题数。更多设置展开追问上限；个人化入口可粘贴/上传文字版 JD、上传文字版简历，展示原文片段和提取结果供用户确认；确认后才影响选题。没有个人资料时不出现上传前置步骤。服务端核对必需环节和优先能力是否有合格题；缺少时显示具体缺口和调整入口，筹备中的方向不能开始。

## 模拟面试：答题与反馈

```text
后端开发工程师                              查看配置  结束练习
────────────────────────────────────────────────────────
技术交流 · 当前环节                                    进阶
━━━━━━──────────────────────────────────────────────────

如何设计一个可靠的缓存更新策略？
在读多写少的业务里，如何保证缓存与数据库的一致性？
资料来源 1

你的回答
┌ 用户已提交的回答 ┐

面试官                                      追问 1 / 1
如果删除缓存失败，你会如何发现并补偿？

────────────────────────────────────────────────────────
你的回答
[ 输入你的回答……                                  ]
Ctrl + Enter 提交                 0 字       [ 提交回答 ]
暂停                                    不会，跳过
```

顶部岗位栏、滚动问答区、固定输入区构成页面的三个纵向区域。当前问题直接排在纸面上；已提交回答使用浅灰底。中文输入法组合期间快捷键不提交。处理时答案保留，原位显示阶段文字，暂停和跳过暂不可用且有原因。

模拟面试显示当前环节、本场优先能力和“待了解 / 信息不足 / 已了解 / 不适用”的证据状态，不显示预计题数或百分比。整场满足覆盖条件后显示完整报告；用户结束、保护上限或题池耗尽时显示部分报告和未覆盖项。候选人可输入反问，也可选择“没有问题”；没有项目经历可跳过经历评价，转入标明假设的情境。跳过的题组无分数。只有技术事实题展示资料来源；来源抽屉在结束前只展示文件信息，结束后展示片段示例。

## 试题练习 `/question-practice`

```text
试题练习
岗位方向 [ Python 后端 ]   能力 [ MySQL 索引 ]
难度 [ 进阶 ]             题型 [ 全部 ]
当前可练 8 题                         [ 随机抽一题 ]

MySQL 联合索引在什么情况下可能无法用于这个查询？
[ 输入回答…… ]                         [ 提交回答 ]

本题反馈 · 需要补充执行计划的验证方法
值得保留 / 需要调整 / 参考答案与依据
[ 重答本题 ]                           [ 下一题 ]
```

一次只展示一道已审核题，不显示“第几题 / 总题数”。提交后立即展示本题反馈；“重答本题”保留首次答案和反馈，创建关联的新尝试；“下一题”在当前筛选池重新随机抽取，近期已做题优先排除，允许重复时明确提示。无合格题时显示调整筛选入口。该入口不显示自我介绍、候选人反问或整场模拟面试分数。

```text
资料管理                                      [ 上传资料 ]

个人知识库 [ 未选择 ▾ ] 新建知识库

[ 搜索文件名 ]   [ 全部状态 ▾ ]   检索测试
文件名                          状态       片段数  参与  操作
────────────────────────────────────────────────────────
Redis 核心知识与实践.md       已就绪        18      ●    ⋯
MD，24 KB，版本 1
────────────────────────────────────────────────────────
项目复盘与表达.doc           失败           —      ○    ⋯

```

列表直接排在页面上，行间用细线分隔。手机上每份文件改为纵向文件行，片段数隐藏。详情从右侧抽屉打开，移动端全屏。上传、替换与重试展示演示状态；当前前端没有实际上传或解析服务。

系统岗位包与已审核资料只读展示；本页的增删改针对个人资料。编辑个人岗位从右侧 640px 抽屉打开，顺序为岗位名称、JD、分析岗位要求、项目背景、能力列表、保存岗位。检索测试是个人资料管理内的独立视图，提供问题输入、结果编号、来源版本和片段正文。无命中时提供返回资料管理的动作。

历史列表保留岗位方向、前端主框架、状态、时间和主题筛选。分数为 `null` 时写“未评价”，不可用 0 或破折号代替。列表行通栏可打开报告。

## 练习报告

报告最大宽 800px，顶部依次是返回入口、标题、日期与状态、报告/问答记录页签。报告内容从整体表现、统计、优先练习方向到题组回顾；题组回顾可切到对应问答。问答记录按提交顺序展示问题与回答。新产生的演示记录没有真实评价，明确显示“未评价”；预置历史分数明确标为示例。

## 响应式验收

在 1440、1280、1024、768、390px 检查横向滚动、固定输入区、侧栏显隐和列表换行。弹窗与抽屉在手机上占满视口，所有图标按钮需有可访问名称。浅色、深色及跟随系统三态均应能完成配置、答题和报告回看。
